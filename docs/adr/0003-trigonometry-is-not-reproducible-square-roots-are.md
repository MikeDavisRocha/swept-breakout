# Trigonometry is not reproducible; square roots are

The README claimed a run replays exactly from its seed and input stream. The
first time that claim was actually checked against an engine other than V8, it
was false.

Computing the committed replay hash inside three engines gave three answers:

```
Node        (V8)             853ae585
Chromium    (V8)             2c64d809
Firefox     (SpiderMonkey)   96d63521
WebKit      (JavaScriptCore) 96d63521
```

Two things are wrong there, and the second is the real one.

**The solver used `Math.sin` and `Math.cos`.** Both are
implementation-approximated — the spec permits any implementation within a loose
tolerance — and the engines genuinely differ. Every launch and every paddle
bounce converted an angle into a direction through them, so a rally diverged the
moment it left V8. A game that reproduces in Chrome and not in Safari does not
reproduce.

**And the test's input stream was itself built from `Math.sin`.** That is why
even the two V8 builds disagreed: they ship different V8 versions with different
sine implementations, so they were replaying *different inputs*. The hash was
testing the browser's trigonometry as much as the game.

## The fix is to never ask for an angle

Both places that set the ball's direction now take a **horizontal share** rather
than an angle, and derive the vertical component with a square root:

```ts
const x = clamp(shareX, -1, 1);
const y = -Math.sqrt(1 - x * x);
```

`Math.sqrt` is exactly specified by IEEE 754. Every conforming engine returns
the same bits, always. The paddle's spread is stored as `sin(60°)` written out
as the literal `0.8660254037844386` rather than computed, so no trigonometry
survives anywhere in the simulation.

The recorded input stream is now generated by the seeded PRNG, which is integer
arithmetic and a division by a power of two — identical everywhere.

## Consequences

- **The claim is now checked, not asserted.** `npm run cross-engine` computes
  the hash inside Chromium, Firefox and WebKit and fails if any disagrees, and
  CI runs it on every push. Chromium is a control: if it ever parts company with
  Node, the harness is broken rather than the solver.
- The paddle's response changed very slightly. Mapping the offset linearly to a
  *share* is not the same curve as mapping it linearly to an *angle* — an offset
  of 0.5 now leaves at 26 degrees where it used to leave at 30. It is, if
  anything, the better curve: more resolution near the centre, where the player
  is aiming most carefully.
- Sine and cosine are still used freely in the renderer, for spark directions
  and shake. Nothing there feeds back into the simulation, so nothing there can
  move a bounce.
- **This is what a same-engine test cannot do.** The suite was green throughout,
  35 tests including a replay test, because Node agrees with itself. The defect
  was outside the tests until an engine that was not V8 was asked the question.
